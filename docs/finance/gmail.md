## Ephemeral statement inspection

Use the authenticated Gmail connector's `read_email(format: "metadata")` for the top-level From and Authentication-Results headers and `read_email(format: "raw")` for the same immutable message ID. In the native connector, RAW is returned as base64url RFC 2822 MIME in `structuredContent.raw`. The worker must consume that value in memory inside the authorized environment. [Gmail message formats](https://developers.google.com/workspace/gmail/api/reference/rest/v1/Format)

[The statement inspector](../../tools/pti-mcp/scripts/inspect-finance-gmail-statement.mjs) requires matching metadata and RAW message IDs. It recognizes the named issuers through the first Google MX Authentication-Results header and an aligned DMARC pass. It decodes bounded MIME parts and checks for PDF framing and an encryption declaration at the cross-reference trailer or stream. It handles PDF, octet-stream and the observed CDSL binary part, and separates an unreadable child from valid MIME siblings. Its output contains only issuer domain, verification state, MIME class, byte count and diagnostic codes. [MIME transfer encoding](https://www.rfc-editor.org/info/rfc2045/) · [Multipart MIME](https://www.rfc-editor.org/info/rfc2046/)

On 22 November 2026, same-message RAW reads yielded five inspected PDF parts from HDFC combined, HDFC Millennia current and archived, CDSL CAS and Groww mail. Each PDF trailer declared encryption. The CDSL message also had one unreadable child MIME part. All five remain `unparsed`. Issuer dates, opening and closing balances, posting rows and household account ownership were unavailable from this inspection. The UPI parser was rerun using the same Google MX and domain-alignment check and still accepted five of eight candidates.

To ingest a statement, cross-check its actual issuer and confirmed household instrument first. A trusted local PDF reader may extract rows when the owner has separately authorized the document's access method. Keep source bytes and credentials out of arguments sent to PTI, logs, persistent files and scheduler prompts. Use an exact issuer layout profile for booking dates, stable row positions and integer INR paisa. Check debit/credit direction, statement date bounds, and opening-to-closing balance where the issuer supplies it. Send only validated sanitized evidence to `finance_ingest_email`. Leave unavailable, unreadable, or ambiguous results as `unparsed` with a genuine coverage gap. A PDF filename, trailer or subject does not establish successful extraction. This diagnostic does not decrypt documents or post ledger entries.
