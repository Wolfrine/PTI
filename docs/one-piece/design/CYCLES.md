## Account identity boundary correction

The parent identified that external PTI sign-out/account switching could leave a previous UID's player/session in memory and permit a late profile/API continuation to write into the replacement context. The authorized fix adds `identity.mjs`: each actual UID change increments an account generation, destroys local playback and replaces all identity-owned state and queues while retaining the public catalogue and requested deep link. Same-UID refreshes do not destroy playback. New-account local progress is restored only after that reset.

The control client snapshots UID/generation and checks before and after token acquisition, response delivery and JSON parsing, including failures and401 refreshes. The app also checks SDK-current versus observed UI UID, guards direct Firebase profile success/catch paths and multi-await playback/account continuations, and prevents old finally blocks from clearing a new account's busy/queue state. Player/dialog callbacks are generation-scoped. No DOM, CSS, fixture or LocalPlayer implementation changed.

All19frontend tests pass. Seven new regressions cover state destruction/reset, switching during token retrieval, switching/sign-out during deferred responses, old401 rejection without retry, A→B→A/JSON races, stale network failures and a switch during forced token refresh.
