# Concurrent restart request failure: engine marker initialization

The independent duration owner retained failed attempts2/3 before the three-consumer timing barrier. These are failures, not short capacity passes. In attempt3, source1001's first64KiB GET received HTTP500 `text/plain`, without its required length/range metadata. The same production request for1000 received206 `video/mp4` and its decoder advanced. The strict static helper correctly refused the500.

Private engine log inspection found two corresponding errors, at2026-10-18T12:16:03.856Z and12:17:15.708Z. Both report the file basename `.jellyfin-transcode` as in use by another process. A role-only path comparison confirmed it is the configured owned processing-root marker, outside prepared renditions; it is **not** a video, original, subtitle or database file. The marker's observed CreationTime/LastWriteTime was12:17:15, the concurrent first-request instant. No credentials, full private paths or playback URLs are copied here.

Pinned sourcev12.2 supplies a concrete startup-race hypothesis:

- [`GetTranscodePath`](https://raw.githubusercontent.com/jellyfin/jellyfin/v12.2/MediaBrowser.Common/Configuration/EncodingConfigurationExtensions.cs) invokes `CreateAndCheckMarker` for the configured processing directory.
- [`BaseApplicationPaths`](https://raw.githubusercontent.com/jellyfin/jellyfin/v12.2/Emby.Server.Implementations/AppBase/BaseApplicationPaths.cs) separately checks whether the marker exists and then creates it; that sequence has no shared request lock.
- [`SystemManager.GetSystemInfo`](https://raw.githubusercontent.com/jellyfin/jellyfin/v12.2/Emby.Server.Implementations/SystemManager.cs) invokes `GetTranscodePath` and returns `TranscodingTempPath`. The authenticated [`SystemController`](https://raw.githubusercontent.com/jellyfin/jellyfin/v12.2/Jellyfin.Api/Controllers/SystemController.cs) exposes this as `/System/Info`.

The first correction made one serialized authenticated `/System/Info` call immediately after encoding configuration, before viewer admission. It requires the effective processing path to equal the exact canonical owned root. **Actual smoke attempt4 disproved this as a sufficient fix:** at12:25:13.962Z source1000's first range still returned500; source1001's request at.998 received its exact206 and decoded. The failure swapped episodes. `media-production-duration-attempt-4-marker-warmup-smoke.json` preserves this counterexample. The current private exception again identifies the processing marker, not video bytes. No hour started.

Further pinned primary source explains why an earlier marker read was insufficient. [`FileHelper.CreateEmpty`](https://raw.githubusercontent.com/jellyfin/jellyfin/v12.2/src/Jellyfin.Extensions/FileHelper.cs) opens with `FileMode.Create`, read/write access and `FileShare.None`. [`TranscodeManager`](https://raw.githubusercontent.com/jellyfin/jellyfin/v12.2/MediaBrowser.MediaEncoding/Transcoding/TranscodeManager.cs) calls `DeleteEncodedMediaCache` in its constructor; that routine enumerates and deletes all transcode-directory files, including the existing marker. [`VideosController`](https://raw.githubusercontent.com/jellyfin/jellyfin/v12.2/Jellyfin.Api/Controllers/VideosController.cs) depends on this manager. Thus lazy video-controller initialization can remove a marker after `/System/Info` initialized it. The companion's cache purge allowlist does not delete that marker; it is not blamed for this observed failure.

The revised correction admits every authenticated fetch through one per-client header queue: JSON administration/library/probe calls, owned progressive generation, subtitles/HLS and complete static video all share it. Admission releases on **actual fetch settlement at headers**, before any body consumption; streaming bodies remain concurrent. A cancelled queued ticket cannot overtake its predecessor. Caller cancellation/deadlines return promptly, while an underlying operation ignoring abort retains the gate until it actually settles. Late response bodies are cancelled without waiting on their cancellation promise. The queue has a32-ticket cap and a30-second caller admission bound; a permanently uncooperative native fetch fails closed rather than starting overlapping initialization. Existing runtime recovery owns that failure. The strict static helper, byte bounds, source roles and caption lineage are unchanged; no500 retry conceals the failure.
