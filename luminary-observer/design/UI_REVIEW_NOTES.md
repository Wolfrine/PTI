# Luminary UI Review Notes

## Review — 2026-09-23

### What is working

- The product posture is unusually clear: observation before interpretation.
- Capture actions are simple and understandable.
- Raw observation, derived pattern, causality and intervention remain conceptually separated.
- Reduced-motion support and performance intent were considered.
- The implementation is coherent enough to function as a prototype.

### Why the visual direction is rejected

The current implementation uses a very common generative aesthetic vocabulary:

- dark field;
- cyan / mint / violet radiance;
- concentric/orbital geometry;
- glowing point;
- generic network nodes for “patterns”;
- rounded surfaces and pill CTA;
- serif-as-premium paired with utility sans;
- fade / translate / scale / pulse as the bulk of the motion language.

This creates competence but weak identity. The visual system can plausibly fit many unrelated AI, meditation, consciousness, scientific or “future” products.

### Structural issues

- Entry behaves like a styled narrow card/shell rather than convincingly creating a “field the user enters.”
- Desktop mostly widens the phone composition; it does not exploit space to create a distinct experience.
- Patterns defaults to the most obvious representation of emergence: connected glowing nodes.
- Motion is mostly micro-animation. It does not yet establish a unique material/temporal behavior for Luminary.
- The repo contained no durable evidence of a real reference pack, multiple art-direction candidates, or an independent visual critique before the v1 runtime was propagated.

### Do not fix by

- adding more glow;
- adding Three.js/particles simply for spectacle;
- increasing animation complexity;
- swapping fonts while retaining the same composition;
- creating another dark “scientific” theme;
- polishing all existing cards.

### Next proof

Only redesign three representative surfaces first:

1. Entry;
2. Observe;
3. Patterns.

If those three establish a distinctive language, then propagate it.
