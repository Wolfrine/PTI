# Module chat lifecycle

The owner approved implementation on 2026-11-02: related outcomes in one canonical project/functional module reuse one native parent chat. Each outcome keeps a distinct task/work key and current mode, authorization, progress and audit; same-outcome continuation retains its task. Parent-led native children are preferred for independent lanes with non-overlapping ownership, while tiny/dependent work stays serial. No new execution or context-count caps are introduced.

Plan and verification sequence:

1. Inspect the live 0.4.3 source, installed state and dirty main checkout; preserve unrelated Velum changes and running services.
2. Separate caller source, router selection and runtime-learned native identity; add transactional owner/module affinity without fuzzy title routing or historical migration.
3. Cover exact retries, related/different modules, physical aliases/checkouts, reservations, mode changes, native suitability and explicit evidence-based rotation with deterministic mocks.
4. Build/test both packages, deliver through main and the existing shared MCP workflow, update the existing private plugin with a release guard, and activate only an idle safe worker. Record any installed/hosted gap explicitly.

The registry is one document per explicit module and canonical physical project/checkout under the existing server-only owner namespace. It stores a pointer/revision and task provenance, not conversation text. Module reservation starts before native thread creation and shares the task admission transaction. A busy module returns its owner; new parents are never a numerical-concurrency workaround. Local identity locks and native unfinished-turn checks remain independent protections.

`sourceThreadId` is the immutable caller-selected source or explicit null; `selectedThreadId` is the initial router choice; `threadId` is learned execution identity. Legacy records lacking source provenance only accept a provably identical retry, or require explicit continuation/new work identity. Exact request hashes include module/rotation inputs and are not weakened.

Mode changes require a new task with current authorization and instruction/permission refresh on the reused thread. `notLoaded` is suitable persistence. Native archive detection uses exact-ID metadata pagination in the selected directory, with no transcript hydration. Confirmed missing/archived/incompatible automatic selections may rotate and audit the predecessor/reason. Explicit source threads, active parents, unfinished turns, same-outcome threads and uncertain protocol failures never silently change parent. Context bloat requires an explicit reason and compact project handoff; no arbitrary turn/token/age threshold, automatic archive/delete or private-message copying is added.

Regression evidence and release/activation identifiers belong in the F-drive delivery report, separate from owner acceptance. No new live chats are required for tests. The current implementation remains in the existing native parent.

Rollback: revert this scoped change through main and restore the prior installed release only when idle. Existing no-module tasks and the prior worker protocol remain compatible. Do not delete registry/task history or restart unrelated work. Stop claiming module routing is available if host and worker capability versions differ.
