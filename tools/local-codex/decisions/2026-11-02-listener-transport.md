The owner approved the correction in the native development conversation on 2026-11-02. The previous audit (`F:/Workspace/Support/LocalCodexBridge/harness/reviews/audit-2026-11-02-polling-design.md`) found three-second active/fifteen-second idle work polling, heartbeat writes on each call, and repeated queue queries within a batch. Its operation projections were code-derived estimates, not billing measurements.

Retain: one persistent owner-only Firebase SDK listener on a content-free dispatch marker, transactional API claims and controls, separate thirty-second batched health/lease maintenance, one queue query per page, local task-file events, progress deduplication including telemetry-only suppression, and a listener baseline without an extra read for hosted task waits. FirebaseServerApp uses the existing owner's ID token and auth refresh; jobs stay server-only. No service key, new account, model/permission change or execution cap is introduced.

Regression risks are missed notifications, reconnect/refresh gaps, stale lease or generation control, crash/retry duplicate work and access-rule overlap. Tests cover queue pages, quiet maintenance, atomic marker writes, duplicate controls, listener cleanup, local file replacement, no-loss wakeups, task identity, concurrency and rules isolation. Live verification must demonstrate a real scheduled worker, idle counters and notification-to-result delivery. ChatGPT still makes bounded listener-backed calls; Firestore alone cannot initiate an ordinary conversation turn.

Rollback: retain hosted compatibility for older `/poll` workers and the installed 0.4.2 release. If dispatch/lease/cancellation or privacy fails, stop acceptance, preserve tasks, and restore the previous worker only while idle; revert the scoped source release through main.
