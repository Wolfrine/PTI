# Exact feedback scope for usage reviews

The Nov 4 and Nov 5 seven-day reports both reached the hosted feedback endpoint's most-recent-100-job bound. The Nov 5 report contains 91 ordinary generations but no explicit owner verdicts. That does not establish absent feedback outside the returned set. The previous decision identified this coverage gap for follow-up.

Use exact remote task IDs from the existing local-to-remote identity map for local generations in the review window. The authenticated review endpoint multi-gets those owner-scoped documents and applies its existing sanitizer. A request batch contains up to 100 IDs; the collector processes every batch without an overall lookup cap. This sizes transport and does not restrict tasks, children, nesting or execution time. Unrelated hosted history is not scanned. Legacy empty-body callers retain recent-100 behavior; an explicit empty selection returns no jobs.

The hypothesis is that explicit identities remove the recency cutoff while keeping the review private and scoped. The expected benefit is reliable feedback lookup coverage for the selected local records, not measured time/token savings. Missing remote documents, unmapped local records, absent feedback and generations outside retained outcome history remain unknown. The existing local scan and retained metadata still bound historical evidence. The report exposes job lookup coverage separately from actual owner verdicts.

Risks include wrong identity mapping, partial batch success being treated as complete, legacy servers ignoring the scope, and leaking contents through a new path. Require the returned-plus-missing IDs to account for the exact batch without duplicates; reject legacy or mismatched responses. A failed batch leaves sync unavailable. Reuse the existing owner authorization, credential, sanitizer and generation-bound verdict mapping.

Verification must cover a task older than the recent 100, more than 100 total requested IDs, same-window old-task continuations, missing/unmapped IDs, generation matching, duplicate/mismatched replies, a later batch failure, empty selections, legacy callers, owner denial and sanitized output. Run the normal worker and hosted suites, obtain independent review, deploy through main, and execute a real metadata-only sync against the hosted route. Activate the installed collector through the normal windowless installer only while idle.

Retain after those checks and live coverage verification. Roll back the scoped collector/endpoint together if identity isolation or sanitizer regressions appear. Preserve explicit incomplete coverage when reverting; never invent owner feedback or replay tasks to test this change. No model, permission, authentication or work-cap policy changes are authorized by this decision.

Pre-deployment result: all 55 worker tests and 167 hosted tests pass; both builds and the Home contract pass. Independent read-only review found no blocking issue and separately passed all 9 review tests and 55 hosted relay tests. The earlier failing test fixture lacked its owner-outcome timestamp; it was corrected without changing production behavior. Keep the real hosted/installed verification and final retain decision in the dated F-drive review record; local tests alone do not prove activation or owner acceptance.
