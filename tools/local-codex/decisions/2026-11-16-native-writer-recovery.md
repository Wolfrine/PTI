## Smallest retained change

1. Read metadata only from the native journal path returned by official `thread/read`, verifying its session ID. Incrementally retain turn start/activity/terminal envelopes, never transcript content. Persisted completed turns or exact terminal events establish outcome; unconfirmed interrupted exports remain unknown. This observation does not acquire/release native ownership.
2. Reconcile local handoff receipts/cache against their exact turn or generated marker, including legacy `not-started` receipts whose input was actually consumed. History returns compact matching receipt metadata. Existing terminal hosted audit snapshots remain immutable; a fresh history operation supplies the correction.
3. Keep the same authorized pending queue entry behind the native owner. Do not reopen the app on each observation or duplicate uncertain input. Normal queue consumption serializes native writers; no separate resume competes with the desktop.
4. Keep a desktop operation's existing hosted lease/reservation and `get_task` lifecycle until confirmed terminal observation. A reader/transport error after a matching durable receipt becomes a visible `observation_error` with unresolved state, not false native failure; input is never resent. Reuse the existing relay maintenance cadence; no new process/schedule. Bounded progress/final text, observation basis, activity time and truncation fit the existing result field. ChatGPT still must poll; this does not push a new ChatGPT turn after polling ends.
5. Recover an uncancelled **edit** ownership failure only before any native turn/tool call, after its failed standalone worker exits. Use the same hosted task/generation/request and exact native parent with verified model/effort; retain the failed local attempt in `result.recovery`. Never automatically broaden inspect to app permissions. Other failures follow the existing failure path.
6. A queued cancel removes only that exact pending entry. After consumption, unavailable native stop is explicit and observation continues. A terminal event is not fabricated from cancellation intent. If the native owner never progresses and supported control stays inaccessible, work remains visibly unresolved. The honest fallback is durable queue + normal native completion/restored supported control, not an owner-only desktop instruction, forced stop, fresh key or arbitrary rotation.

## Checkout guard decision

Retain the conservative checkout edit exclusion. Current requests have no enforced file-ownership list and a read-only model can inspect transient edited files/shared Git state. Removing exclusion would not preserve same-file/Git write coordination. A safe file-level design would need enforced path ownership plus a separate shared Git gate across host and worker. That is larger than this repair. Both guards remain unchanged, with the exact contention source reported separately. No additional count/duration restriction is introduced.
