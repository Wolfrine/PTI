# Independent owner Chrome provider

PTI's separate provider controls **real local Chrome** through Google's documented [chrome.debugger](https://developer.chrome.com/docs/extensions/reference/api/debugger) and [Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) APIs. It is not ChatGPT Desktop Computer Use. The official preflight, OpenAI extension, subscription sign-in and plugin/App IDs stay unchanged. There is no remote-debugging port, raw CDP socket or credential copying.

## Installation and use

1. In `tools/local-codex`, run `npm run build`, then the verified local `chrome/install.ps1` with process-only ExecutionPolicy Bypass if needed. No admin elevation, service, browser flags, credentials or global Codex setting is added. The installer registers only `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.pti.local_codex.chrome` in both registry views, freezes provider 0.1.1 under `F:\Workspace\Support\LocalCodexBridge\chrome\releases\0.1.1`, records file hashes and restricts the provider/IPC/evidence tree to the current owner + SYSTEM. The public manifest key fixes independent extension ID `njjcfpeiadgkanlcmifkjcifihccfigo`; this is not an OpenAI identity or a credential.
2. **Chrome-required interactive step:** in the intended personal profile, open `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select `F:\Workspace\Support\LocalCodexBridge\chrome\releases\0.1.1\extension`. This is Google's [documented development install](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked). Do not edit Preferences, sideload by policy, copy profiles, relaunch a managed profile or weaken Chrome/Windows policies. A policy denial is a platform gate. The unrelated running Blinkit Chrome profile is not modified. The initial 0.1.0 extension folder is also compatible with this native protocol if it was already loaded during setup; no second permission gesture is needed.
3. Activate worker 0.4.9 through [maintenance-upgrade.md](maintenance-upgrade.md). It adds only task-scoped `pti_chrome` MCP startup overrides to the existing app-server; no new parent, model, account or global MCP setting. Worker 0.4.8 does not automatically advertise these tools. Existing hosted MCP 0.4.6 delegates normal jobs unchanged; no hosted redeploy is needed. Plugin source 0.4.8 updates instructions; account publication is a separate owner-host operation and was not performed here.
4. In each authorized job, the native worker calls `chrome_status`, then `chrome_request_session` with the exact URL/objectives. Open that URL in Chrome, click **PTI Owner Chrome**, select the exact task, confirm other automated desktop operators have released the foreground, choose 5/15/30 minutes and click **Allow selected task on this tab**. Chrome's debugger banner and the ON badge remain visible. Nothing attaches/navigates before the owner action. Per-task tab/site consent is intentional.

## Interface / security

Tools: `chrome_status`, `chrome_request_session`, `chrome_state`, `chrome_screenshot`, `chrome_navigate`, `chrome_pointer`, `chrome_touch`, `chrome_key`, `chrome_text`, `chrome_viewport`, `chrome_release`. Pointer CSS coordinates/down/up support canvas/WebGL and dragging/held controls. Touch supports five points and explicit end/cancel. Keyboard supports ordinary page keys without OS/browser modifier shortcuts. Viewport emulation is bounded to 240–2560 by 240–1600. Screenshots are real tab-viewport pixels, including WebGL. Visible DOM reads use a fixed isolated-world function; bounded accessibility summaries omit textbox values. Page content is untrusted data.

Only `http://localhost:4173` and `https://taleweald.firebaseapp.com` are allowed. A grant binds one live hosted task + local worker PID + generation + request + tab + origin + random run ID. Same-origin navigation is allowed. Query/credential URLs, cross-site navigation, arbitrary JS/CDP, cookie/storage/network APIs, downloads, password entry, hidden-tab operations and desktop-wide capture are excluded. `inspect` tasks can obtain approved reads/screenshots, but cannot navigate/type/click/emulate. Audio capture/analysis are **unsupported**; speaker playback is **unverified**. Command delivery never establishes gameplay or audio acceptance.

Chrome starts a windowless native stdio shim; `allowed_origins` admits exactly this extension. No public/loopback port. Owner-private files carry IPC, pending requests and evidence. The native host checks a current relay claim, recent connectivity, active worker/task/generation and cancellation before dispatch and before saving observations. One global native lock serializes provider sessions across profiles. Commands are consumed before dispatch so crashes cannot replay clicks. The extension separately checks the grant, foreground Chrome window/tab, origin, navigation generation and expiry. Navigation/revocation during a capture discards its response. Owner release, task/claim loss, consent expiry, tab closure/site change or Chrome disconnect revokes access; held inputs and emulation are released where the original page is still eligible. Idle connections close after a short UI/session settling period. No recurring Windows jobs.

The provider cannot inspect/arbitrate an unrelated official Desktop operator without crossing that boundary. Owner foreground-exclusivity attestation plus Chrome's debugger attachment ownership are the supported boundary. Never steal another debugger attachment, override policy or retry an uncertain input blindly. Observe state first.

## Evidence and live status

`chrome_status` reports provider/readiness, proof kind, route, limits, reason, timestamp and next step. Installation alone is never authorization. Hosted `get_capabilities` still describes the official Desktop/manual QA broker; use the native job's `chrome_status` for this independent provider. Normal ChatGPT/mobile supervisors delegate through the existing plugin and receive actual native-agent observations/receipt references in job results.

Actual screenshots/state receipts live under `F:\Workspace\Support\LocalCodexBridge\chrome\evidence\<task-id>`. Receipts record run/task/generation/tab/origin, provider/provenance, capture time, size and SHA-256. Screenshot tools also return an image to the native agent. `ipc\operations.jsonl` records metadata only, without typed text/page content. A capture receipt is not owner acceptance; `playable-tested` requires actual observed gameplay. No mock receipts/fixtures are generated.

## Recovery

Use **Release Chrome access** or Chrome's debugger banner Cancel. Revoked/finished tasks need a new request/grant, never copied lease files. If another profile owns the native host, release it normally; never terminate all Chrome/Node processes. To disable the provider, release it and let its connection close, then run local `chrome/unregister.ps1`. It refuses a live native host, removes only matching HKCU registrations and retains a disabled pointer plus all files/evidence/bridge history/config. Remove the extension through Chrome if desired. Provider updates use new immutable releases after the previous connection closes; never overwrite loaded source. Worker rollback uses the maintenance runbook's frozen prior seven-file release/fence.

No AI-generated tests, fixtures, Playwright/e2e scaffolding or CI jobs. Use minimal syntax/build validation and actual authorized observations. Existing CI-consumed safeguards are preserved; no hosted deployment/CI test run is needed for this local-only release.
