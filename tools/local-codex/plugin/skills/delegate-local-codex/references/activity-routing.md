# Activity routing and native leadership

Use the least costly available route that can deliver the owner's requested quality and verification. This is a decision aid, not a resource scheduler, numeric admission gate or permission grant. Length, a coding keyword, an idle PC or available quota alone does not justify new work.

| Evidence needed | Usual route |
|---|---|
| Explanation or small edit with all context supplied | ChatGPT |
| Connected account data, research or documents | Existing authenticated tools in ChatGPT |
| Local source, Windows, build, GPU or substantial repository engineering | Native Codex through the helper |
| Browser/desktop interaction | Official tools available in the executing turn |
| Device, audio or experiential acceptance | The actual intended environment; missing access leaves the gate open |

Give native Codex the outcome, constraints, exact source checkout and required evidence. Native Codex owns its plan, useful independent subagents, integration, critique and delivery. New work starts fresh; explicit task/thread continuation remains available. Do not enforce module parents or prescribe a shell-by-shell execution script.

## Existing allowance observations

When allowance affects an owner decision, read the existing PTI Apps owner-scoped `codexProjects/codex-usage` document using its authenticated connection. The existing quota collector owns its readings, runtime, schedule and publication. Do not alter it, create another collector/store/schedule or infer missing readings.

Check source, successful observation time, section status, bucket/window, remaining headroom and reset timestamp. Publication time does not refresh an older successful section. Preserve missing/null as unknown; known zero is different. Overlapping windows and latest-response counters cannot be summed into task cost or savings. Codex counters do not establish ordinary ChatGPT Chat allowance.

Earned-reset metadata is contingency information. It does not authorize redemption or extra work. Never consume a reset automatically. Compare relevant freshness/headroom with actual priorities and deadlines; there is no universal usage-percent threshold and no invented token prediction. Small answers need no PC or usage probe.

## Native selection and evidence

Request the owner-selected `gpt-6.2-sol/xhigh` for new work. Verify actual catalog support and native execution metadata. Saved configuration, a request or a prompt does not prove the model ran. Preserve active executions and report their real selection. A different model requires current owner authorization; do not silently substitute one.

Ordinary native execution is the supported default. Activate a Goal only for explicit owner intent with a concrete objective and finish conditions; include a budget only when supplied. Transport terminal state does not prove a later autonomous continuation completed. Do not activate a Goal, watcher or schedule merely to keep working.

Supervise meaningful milestones during the current ChatGPT turn. Completion is separate from owner acceptance. Use current scoped observations, disclose missing coverage and avoid claims of effectiveness from source changes, agent count or protocol success alone.
