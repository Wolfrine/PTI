# Velum Auto Review

Auto Review lives in Velum Studio. The owner approves a text editing seed, up to six exact unshared image versions from Private/References, and the configured image model. They confirm permission and non-intimate scope with every revision of those settings. The prompt-construction guidance has its own editor, approval and version. It controls phrasing and leaves the editing seed intact. Qwen-Image 2.1 Turbo is the default. The selected model must be advertised by the approved, recently seen PC.

## Run and review

- The owner starts one run. Auto Review rotates through the approved source pool, verifies current folder lineage, permissions and the exact approved version, and chooses one eligible image. It skips missing or changed versions. The run, Studio job, and admission counter are created together. The seed revision, independent prompt-guidance revision, Drive version, normalized reference hash and numeric sampling seed stay attached. Source originals remain in Drive.
- Vision Model 1, local Qwen3-VL 2B Instruct, reads the verified reference and approved seed and proposes one concise edit prompt. A refusal or invalid response stops that run before image inference. The worker seals the derived prompt before sampling and executes it through the existing configured image model. Normal Studio jobs retain their existing prompt path.
- Vision Model 2, local Qwen3-VL 4B Instruct, compares the verified normalized reference and exact PNG against the approved seed and actual edit prompt. It proposes an observation, learning and a revised seed. A failed comparison retries at most once against the existing PNG, without sampling again. If comparison stays unavailable, the owner can still review the staged image.
- When the owner has Auto Review open, a verified completed PNG is sent directly to the unshared Private/Review staging folder. The browser uses the existing Drive upload grant and reserves one file ID before upload. An existing folder grant avoids a per-image Picker action. If Google denies folder access, the owner can grant the exact folder once through the existing Picker connection. The worker can finish inference and comparison after the browser closes. Staging pauses on hide, close or lock and resumes when the owner reopens Auto Review in an authorized session. The offline Drive endpoint refreshes grants only for the verified owner browser. The approved PC device has no Drive write route.
- The comparison shows the staged edit and the exact normalized reference supplied to the model. Holding peeks at the reference, and tapping or keyboard activation toggles the comparison. Acceptance records the owner's intent before moving the same PNG directly into the existing Private folder. The browser verifies the parent and hash before recording acceptance. The existing gallery Sync discovers the accepted image for Drift and Browse. The staging folder and its contents fall outside that discovery.
- Rejection keeps the PNG in staging and records what the owner observed alongside the separate vision proposal. The owner can edit, save, and approve learning from either outcome and use approved learning to draft new prompt guidance. The proposed seed opens separately as an editable seed draft. Future runs continue to use both approved revisions until the owner explicitly replaces either one. Edits never change past runs.

## Release and usage

Deploy the exact main revision to the existing Velum Hosting target and publish only the reviewed Velum block through the existing shared-rules release lane. Keep activation absent until the production usage baseline and an approved run limit are recorded. The owner-administered `autoReviewControl/activation` document takes integer fields `until` (UTC epoch milliseconds for new admissions) and `maxRuns` (cumulative admissions, including closed runs). Setting `until` to zero stops admissions and queue promotions. Existing queued or running jobs drain within the Studio job lifetime, and their review receipts can be reconciled after the admission window.

There is no new cloud service, scheduler, browser listener, model service, or paid inference call. The app reuses Studio's visible-session status stream. Each admitted run can add up to 2 MiB of reference bytes and 7.2 MB of PNG data before base64 transport and Firestore overhead, one Drive PNG of up to 7.2 MB, plus existing worker progress writes and on-demand review reads. A one-run pilot would need its storage, transfer, and write headroom checked against the live project and Drive quota. The admission cap limits jobs. Reviewing, retrying a transfer, and retaining results consume usage separately.

The worker uses the official pinned checkpoints and local llama.cpp archives in the [model manifest](../../tools/velum-worker/review-vision-models.json). Install under the declared H-drive root after SHA-256 verification. Vision uses one authenticated loopback process at a time, a 180-second watchdog, one shared inference lock, four CPU threads and one GPU workload. A Windows job object tears down the child, including on parent interruption. Before advertising v2, publish the scoped rules, set `review-v2.enabled` in the vision runtime root to `review-v2`, and restart the existing worker while idle. Until that rollout, the worker continues to advertise v1. For rollback, close admission and drain v2 reservations before returning the worker to v1.

## Design and verification

The dialog extends the existing Studio visual direction. The image and hold gesture lead the review, with the decision and owner seed adjacent on desktop and stacked on mobile. The key checks are immediate comparison without layout jumps, legible controls at phone width, and clear distinctions between working, staged, resolving acceptance, accepted, and rejected. Configuration and history use disclosures. Central release 0.2.3 guided the bounded Studio extension.

Independent source review covered the owner scope, local inference, Drive lineage, rules and comparison recovery. A private production run requires owner authentication, approval of an exact source pool and seed, and a bounded production admission. Worker startup and local model readiness are recorded separately from image quality and review acceptance.
