# Velum Auto Review

Auto Review lives in Velum Studio. The owner approves the exact text of the editing seed, the image model, and automatic selection of eligible unshared images in the existing Private folder and its References child. The owner confirms permission and non-intimate scope for eligible images, including consent from any recognizable adults used. Descriptive guidance has its own editor, approval and version. Qwen-Image 2.1 Turbo is the default. The selected model must be advertised by the approved, recently seen PC.

## Run and review

- Batch size is an editable positive integer. The current operational limit is three edits per batch or the remaining approved admissions, whichever is lower. Start selects distinct eligible JPEG and PNG originals by metadata from direct children of the two approved sources. Review staging and Auto Generated are outside source discovery. Sources require a Drive SHA-256 and are limited to 7.2 MB, 24 megapixels, an 8192-pixel edge, and a 1:8 to 8:1 aspect ratio. A run, Studio job, and admission increment are created together.
- The worker rechecks the exact Drive parent, private ownership, version and digest through the existing authorization before opening any source. The pinned worker gets a verification decision and reads the original through the owner's already connected Drive for desktop mount. It verifies the exact bytes and copies them to H: without encoding, resizing, or relaying them through Firestore. Image engines retain their own bounded pixel preprocessing. Failed metadata verification or a mismatched local file ends that attempt before inference.
- Vision Model 1, local Qwen3-VL 2B Instruct, can reject the original or seed on safety or uncertainty grounds. It otherwise returns an optional declarative description of visible details relevant to the owner’s edit. The worker seals the verbatim seed, addition and final prompt before sampling. When an addition is present, two newline characters join it to the unchanged seed. The review shows all three values independently. The local checks cannot infer consent from an image, and configuration approval is required before use.
- Vision Model 2, local Qwen3-VL 4B Instruct, compares the verified original and exact PNG against the approved seed and actual edit prompt. It records an observation before review. A failed comparison retries at most once against the existing PNG. The owner can review the staged image if this comparison is unavailable.
- Start reserves the exact run IDs, source identities and private staging folder under the existing Google connection. Studio can close or lock after the queue is admitted. The PC processes it serially. The Function keeps the owner grant server-side, rechecks Drive lineage and uploads the hash-verified PNG to the reserved file ID in unshared Private/Review staging. Each item has at most two automatic staging attempts. The existing Picker supplies any required exact-folder permission. In unlocked Studio the owner can reconcile the same reserved file if automatic confirmation fails.
- The queue retains every admitted item. Pause holds edits that are waiting to start. Resume releases them. Stop cancels waiting or incomplete transfers. An edit claimed before the cutoff can stage for up to one hour from its claim while the Drive grant and device approval remain valid. Existing staged results remain available for review.
- The comparison shows the staged edit and the verified original. Holding peeks at the source, and tapping or keyboard activation toggles it. Acceptance first records the owner’s decision, then moves the same PNG into the verified Auto Generated child of Private. The existing connection can provision that exact folder on first acceptance and uses one reserved Drive ID to reconcile retries. The existing gallery Sync discovers accepted items in Drift and Browse. Review staging is outside gallery discovery and manual Studio keeps its previous source and management permissions.
- Not Okay keeps the PNG in staging. A reason and feedback are optional. The decision queues one local Vision Model 2 follow-up using the verified original, output, actual prompt and any feedback supplied. The proposed descriptive guidance remains editable and requires explicit approval. The editing seed keeps its separate approval. Prior runs retain their original revisions.

## Release and usage

Release the existing `velumDrive` Function, the exact main revision to Velum Hosting, and the reviewed Velum rules through the existing release lane. The owner-administered `autoReviewControl/activation` document takes integer fields `until` (UTC epoch milliseconds for admission) and `maxRuns` (cumulative admissions, including closed runs). Keep activation closed until usage and the owner-approved cap and expiry are recorded. New reservations expire at the earlier of the admission cutoff and 24 hours. Setting `until` to zero blocks fresh reservations, queue promotion and claims. Use Stop to cancel already reserved waiting items. Staged receipts remain reviewable after admission closes.

The app reuses the existing worker, Function, private grant, Firestore and visible-session status stream. Each run can add up to two scoped metadata checks and two staging attempts, 7.2 MB of result bytes before base64 and Firestore overhead, and one Drive PNG of up to 7.2 MB. Original bytes never enter the cloud job queue. The existing instance cap and approval window bound the cost. No schedule or paid model call is used.

The 26 November review measured the existing Function at 1 vCPU, 256 MiB, request-based billing, a 60-second timeout, and a revision maximum of two instances. Firestore is Standard in Mumbai and the Function runs in Iowa. At list prices the estimates are US$0.003–$0.05 once for the scoped release, or $0.21 for a longer build, and $0.04–$0.15 gross in a normal month including conservative artifact retention. Ten illustrative high-usage runs total up to $0.39 gross including retention. These scenarios assume 32–64 MiB aggregate transfer, 500–2,000 reads and writes each, and 15 MiB of retained Firestore data per run. They assume no credits or shared free allowance. At 18:02 UTC on 26 November, monitored Firestore operations left nominal headroom of 33,763 reads, 13,883 writes and 19,966 deletes for the current Pacific day, subject to ingestion lag and metering differences. The existing Drive mount reported 19.75 GB available. Account-wide Cloud Build, Cloud Run and artifact allowances and eligible credits remain unverified. An approved production admission cap and expiry are still required. See [Cloud Run](https://cloud.google.com/run/pricing), [Firestore](https://cloud.google.com/firestore/pricing), [Cloud Build](https://cloud.google.com/build/pricing), [Artifact Registry](https://cloud.google.com/artifact-registry/pricing) and [Drive quotas](https://developers.google.com/workspace/drive/api/guides/quotas).

The worker uses the pinned checkpoints and local llama.cpp archives in the [model manifest](../../tools/velum-worker/review-vision-models.json). Local originals, journals, generated images, logs and working caches use H:. The separate shared Studio launcher and its protected device state keep their installed paths. The owner DriveFS mapping is recorded in `H:\Workspace\Runtimes\PTI\velum-review-vision\review-drive.json`. DriveFS source reads run in a bounded disposable child. Original-byte Auto Review skips fixed RAM and F: free-space gates. H: space, thermal and VRAM protection, process watchdogs, input integrity, and shared inference locking still apply. Normal Studio and legacy review retain their existing resource gates.

Original-byte jobs require protocol 4. After verifying the Function, Hosting and scoped rules releases, set `review-v4.enabled` in the vision runtime root to `review-v4` and restart the existing worker while idle. Verify the protocol-4 heartbeat and the owner Drive mount before opening an approved admission window. For rollback, close admission and drain existing claims before removing the marker and restarting.

## Design and verification

The dialog extends the existing Studio visual direction. The image and hold gesture lead the review, with the decision and owner seed adjacent on desktop and stacked on mobile. The key checks are immediate comparison without layout jumps, legible controls at phone width, and clear distinctions between working, staged, resolving acceptance, accepted, and rejected. Configuration and history use disclosures. Central release 0.2.3 guided the bounded Studio extension.

Independent source review covers the owner scope, local inference, original-byte Drive lineage, rules and comparison recovery. A production run requires the owner’s approved source scope, seed and descriptive guidance, a connected PC, and a bounded admission window. Local inference readiness, live folder authorization, and rendered owner review are distinct observations.
