## Implementation plan and resulting code

- Keep Firebase `browserLocalPersistence`. Startup and PIN unlock restore without a popup. Privacy lock clears media URLs/thumbnails, active token and pending transfers. BFCache re-entry asks for the same PIN. It does not automatically unlock or revoke the server grant. Explicit Disconnect disables server authority and revokes Google authority where a revocable credential exists; pending/unknown revocation remains visible and blocks automatic reconnection. Existing temporary access is retained only within its old bounded cache. Short access-token recovery records are usable only for revocation. No refresh token enters browser storage.
- `functions/src/velum-drive.ts` is a dedicated v2 owner-only service behind `/api/drive/**`. Firebase ID tokens are checked for revocation, exact UID and linked Google subject. It binds a fixed-origin callback, one-use expiring state, PKCE, nonce and Firebase Hosting's forwarded `__session` HttpOnly/Secure/SameSite=Lax cookie. Refresh credentials and PKCE material use AES-256-GCM with context binding; only exact Secret Manager names are read by runtime. Refresh validates OAuth client, subject, granted scopes and expiry. Revision checks reject late callback/session responses after Disconnect. Rejected issuance and interrupted revocation retain encrypted cleanup authority and are retried without logging credentials.
- Server records use top-level `_velumDrivePrivate`, covered by the existing default-deny Firestore rules. Generic Admin MCP paths explicitly exclude that root. `/api/drive/` bypasses the service-worker cache. No shared Firestore rules or IAM protections are weakened.
- Browse uses a 44px arrow overlay independent of the image opener. Eligibility/destination still use exact folder IDs only. Details preserve the existing image node while reserving preview height. Move/Undo preserve ID, owner, parent and folder/capability guards. A same-session, exact receipt, ten-minute, one-use return marker allows an initial successful OAuth callback to resume the requested action after PIN entry; general startup does not execute arbitrary queued writes.
- Studio still selects internal references in-app. Every Save verifies the local original bytes, reserves one immutable file ID and uploads through `drive.file` into My Drive root. `drive.metadata` places that same owned PNG into exact Private after parent/capability checks. A fresh metadata read must confirm exact Private before success. Interrupted placement is explicitly reported as staged/uncertain and Retry reconciles the same reserved ID. No orphan is silently reported Saved, no duplicate or deletion is introduced, and no per-save folder Picker remains. The explicit external-image Picker remains. Failed selected-save verification clears its affirmative Saved status. Drive app-property hash matching is not an independent Google byte checksum.
