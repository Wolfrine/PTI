Existing temporary access is retained only within its old bounded cache. Short access-token recovery records are usable only for revocation. No refresh token enters browser storage.
- `functions/src/velum-drive.ts` is a dedicated v2 owner-only service behind `/api/drive/**`. Firebase ID tokens are checked for revocation, exact UID and linked Google subject. It binds a fixed-origin callback, one-use expiring state, PKCE, nonce and Firebase Hosting's forwarded `__session` HttpOnly/Secure/SameSite=Lax cookie. Revision checks reject late callback/session responses after Disconnect. Rejected issuance and interrupted revocation retain encrypted cleanup authority and are retried without logging credentials.
- Server records use top-level `_velumDrivePrivate`, covered by the existing default-deny Firestore rules. Generic Admin MCP paths explicitly exclude that root. `/api/drive/` bypasses the service-worker cache. No shared Firestore rules or IAM protections are weakened.
- Browse uses a 44px arrow overlay independent of the image opener. Eligibility/destination still use exact folder IDs only. Details preserve the existing image node while reserving preview height. - Studio still selects internal references in-app. Every Save verifies the local original bytes, reserves one immutable file ID and uploads through `drive.file` into My Drive root. `drive.metadata` places that same owned PNG into exact Private after parent/capability checks.
